# Задание: русский перевод Viva Piñata: Trouble in Paradise

Ты переводишь текст игры Viva Piñata: Trouble in Paradise (Xbox 360, рекомпиляция на ReXGlue SDK) на русский язык. Инструменты уже готовы. Твоя задача — заполнить поле `ru` в рабочих файлах. Собирать файл игры, подключать перевод и проверять его в игре будет Claude после тебя.

## 1. Что лежит в `translation/work/`

| Файл | Что это |
| :-- | :-- |
| `part_001.json` … `part_023.json` | 9 019 уникальных строк игры, по 400 в файле, в порядке, в каком они лежат в игре (соседние строки обычно из одного меню или диалога) |
| `glossary.json` | 1 859 коротких терминов из перевода первой части (ZoG Team, 2007): имена пинат, предметы, меню |

- 4 384 строки уже заполнены из перевода первой части (`"src": "zog"`).
- 4 635 строк пустые (`"ru": ""`). Их нужно перевести.

Рабочие файлы содержат текст игры. Они в `.gitignore`, **не коммить их и никуда не выкладывай**.

## 2. Формат записи

```json
{
 "id": "t00015",
 "en": "If you are busy, new Alerts will wait at the bottom of the screen. To open them press [DPAD_DOWN] then use [LS] and [A] to select one.",
 "ru": "Если вы заняты, новые подсказки будут ждать внизу экрана. Чтобы открыть их, нажмите [DPAD_DOWN], затем выберите подсказку [LS] и [A].",
 "src": "zog",
 "limit": 148,
 "uses": 1,
 "ctx": [],
 "note": ""
}
```

| Поле | Можно менять? | Смысл |
| :-- | :-- | :-- |
| `id` | нет | номер строки |
| `en` | **нет, ни символа** | оригинал; по нему строка находится в игре |
| `ru` | **да** | перевод; пустая строка = в игре останется английский |
| `src` | да | `zog` — из первой части; ставь `gemini` для своего перевода и `zog+gemini`, если исправил строку ZoG |
| `limit` | нет | мягкая цель по длине (≈ длина `en` + 10 %) |
| `uses` | нет | сколько раз строка встречается в игре (один перевод на все места) |
| `ctx` | нет | соседние строки (предыдущая и следующая) для контекста |
| `hint` | нет | есть у 36 строк: вариант ZoG, который не прошёл проверку разметки; можно взять за основу |
| `note` | да | твой комментарий: сомнения, неясный контекст |

Не удаляй, не добавляй и не переставляй записи, не переименовывай файлы, не переводи файлы в CSV. Файлы должны остаться валидным JSON в UTF-8 без BOM. Единственный новый файл, который можно создать, — `translation/work/glossary_tip.json` (см. п. 4.5).

## 3. Порядок работы

1. Один раз запусти проверку, чтобы увидеть исходное состояние (нужен Python 3.10+, команды — из корня репозитория):
   ```
   python tools/tip_text.py check
   ```
2. Бери файлы по порядку. В каждом:
   - переведи пустые `ru`, поставь `"src": "gemini"`;
   - просмотри строки `zog`: исправь явные ошибки и обрезки (см. п. 4.6), поставь `"src": "zog+gemini"`.
3. После каждого файла запускай `python tools/tip_text.py check`. Следующий файл — только когда ошибок 0. Полный отчёт: `translation/check_report.txt`.
4. Ничего не трогай вне `translation/work/`. Не запускай сборку, CMake, кодогенерацию, игру. Не коммить.

**Не запускай `tools/tip_text.py extract`.** Он перезаписывает рабочие файлы, и перевод пропадёт.

## 4. Правила перевода

### 4.1 Разметку копировать без изменений

Валидатор сверяет набор разметки в `en` и `ru`: должно совпасть всё, вплоть до количества. Внутри предложения разметку можно переставлять, но теги должны остаться правильно вложенными.

| Разметка | Примеры | Что это |
| :-- | :-- | :-- |
| HTML-теги | `<br/>` `<br>` `<b>…</b>` `<i>…</i>` `<ds>…</ds>` `<font color=[RED]>…</font>` `<table>` `<tr>` `<td …>` `<div …>` | перенос строки, стиль, цвет, таблицы |
| Кнопки | `[A]` `[B]` `[X]` `[Y]` `[LS]` `[RS]` `[DPAD]` `[DPAD_DOWN]` `[BACK]` | иконки кнопок геймпада |
| Иконки и имена | `[Animal_canary]` `[HEART]` `[LOATHER]` `[TEMP]` и ещё около 130 видов в квадратных скобках | игра подставляет иконку или название |
| Подстановки | `{text}` `{value}` `{asset}` `%s` | игра подставляет текст или число |
| Сущности и спецсимволы | `&nbsp;`, перевод строки `\n`, табуляция `\t` | как есть |

Пробелы, переводы строк и табуляции в начале и в конце строки должны быть такими же, как в `en`.

Содержимое скобок не переводить: `[Animal_canary]` остаётся `[Animal_canary]`, `[RED]` остаётся `[RED]`.

### 4.2 Подстановки и русская грамматика

- Вместо `[Animal_…]` игра подставляет название пинаты в **именительном падеже**. Строй фразу так, чтобы название стояло в именительном:
  - `Buzzenges are drawn by the sounds of a [Animal_canary].`
  - плохо: `…их привлекают звуки [Animal_canary].` (нужен родительный падеж);
  - хорошо: `…их привлекает пение пинаты [Animal_canary].` или `…их привлекает звук, который издаёт [Animal_canary].`
- `{text}` и `%s` — неизвестный текст или число. Выбирай конструкции без согласования: `Лимит времени: %s`, а не «Осталось %s минут».
- Кнопки: `нажмите [A]`, `удерживайте [LS]`.

### 4.3 Длина

- **Жёсткое правило (проверяет `check`).** Строки одного блока игры делят общее место: сумма длин русских строк блока не должна превышать сумму длин английских. Одна строка может быть длиннее оригинала, если соседняя короче. При переполнении `check` пишет `block N: X chars over its budget … (shorten some of: t…, t…)`: сократи какую-нибудь из перечисленных строк.
- **Мягкое правило (`limit`, только предупреждение).** Старайся укладываться в длину оригинала + 10 %. Особенно это важно для пунктов меню, кнопок и подписей: в интерфейсе мало места.
- Сокращения вроде «Морк.» или «Отм.Лечение» используй только в крайнем случае.

### 4.4 Символы

Можно: русские буквы (включая Ё/ё), латиница, цифры, обычная пунктуация ASCII, а также `« » — – … № “ ” „ ’` и неразрывный пробел. Всё это есть в шрифте игры.

Нельзя: эмодзи, любые другие символы Unicode. Кавычки в русском тексте — «ёлочки», тире — `—`.

### 4.5 Терминология и стиль

- Игра семейная и добрая, с лёгким юмором и каламбурами. Обращение к игроку — на «вы», со строчной буквы.
- Термины бери из `glossary.json` и из строк `zog`. Примеры: Piñata → пината (в тексте со строчной), Journal → Журнал, Garden → Сад, Seedos → Сидос, Leafos → Лифос, Professor Pester → Профессор Пестер, Ruffian → Хулиган, Willy Builder → Вилли Стройка, Whirlm → Вирлм, Sparrowmint → Спарровминт.
- Новые имена пинат и персонажей, которых не было в первой части, передавай так же, как ZoG: фонетической транслитерацией (Whirlm → Вирлм). Каламбур переводи, только если он очевиден и укладывается по длине. Каждое новое имя записывай в `translation/work/glossary_tip.json` (`{"English": "Русский"}`) и используй везде одинаково.
- Одна и та же строка может стоять в нескольких местах (`uses` > 1): переводи нейтрально, чтобы подходило везде.
- Не переводить (оставить `ru` пустым или скопировать `en`): служебные строки вроде `DO NOT SHOW`, `RUFFIAN TEXT SHOULD NOT BE SHOWN`, имена людей в титрах, названия `Xbox 360`, `Xbox LIVE`.

### 4.6 Строки из первой части (`src: "zog"`)

ZoG переводили без доступа к коду, и каждая строка должна была влезть в длину английской. Поэтому часть строк обрезана или переведена неточно:
- `Watering Can` → «Вода» (должно быть «Лейка»);
- `Chocolate Coins` → «Шоколад» (должно быть «Шоколадные монеты»);
- `Caw, you're great.` → «Ты крупный.»;
- `Candary first sighting.` → «Кендари - 1 сверка.».

Исправляй такие строки, если хватает бюджета блока (`check` покажет). Термины, которые уже устоялись (имена, названия меню), не меняй без причины: игроки знают их по первой части.

## 5. Когда работа готова

- `python tools/tip_text.py check` выдаёт `0 errors`.
- Пустые `ru` остались только там, где это сделано намеренно.
- Все новые имена собраны в `translation/work/glossary_tip.json`.
- Сомнительные места помечены в `note`.
- В ответе пользователю дай короткий отчёт: сколько строк переведено, сколько исправлено из ZoG, что осталось сомнительным.
